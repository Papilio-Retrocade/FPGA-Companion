# FPGA JTAG Programming via ESP32

## Overview

The FPGA Companion now supports **direct JTAG programming** of Gowin FPGA bitstreams from the ESP32, eliminating the need for:
- External JTAG programmers
- Bootloader dependencies  
- SPI flash wear during development
- Emergency recovery procedures

## Hardware Connections

JTAG signals are permanently connected between ESP32 SuperMini and Gowin FPGA:

| ESP32 GPIO | FPGA Pin | JTAG Signal | Function |
|------------|----------|-------------|----------|
| GPIO7      | A6       | TDI         | Test Data In (ESP32 → FPGA) |
| GPIO5      | C6       | TDO         | Test Data Out (FPGA → ESP32) |
| GPIO6      | A7       | TCK         | Test Clock (ESP32 → FPGA) |
| GPIO8      | B8       | TMS         | Test Mode Select (ESP32 → FPGA) |

## Two Programming Methods

### Method 1: JTAG SRAM Programming (Recommended for Development)

**Advantages:**
- ✅ Fastest - no flash erase/write cycles
- ✅ No flash wear - perfect for rapid iteration
- ✅ Works even with corrupted flash
- ✅ Direct .fs bitstream support - no conversion needed
- ✅ Instant reconfiguration (~5-10 seconds total)
- ✅ Always available - JTAG never fails

**Disadvantages:**
- ⚠️ Volatile - lost on power cycle
- ⚠️ Requires WiFi connection for OTA

**Usage:**
```bash
# Generate .fs bitstream from Gowin IDE (SRAM programming file)
# Located at: impl/pnr/your_project.fs

# Upload via JTAG to SRAM
curl -X POST http://10.0.4.94:3232/fpga-jtag-sram --data-binary @impl/pnr/bitstream.fs
```

**Typical timing:** 5-10 seconds total

### Method 2: SPI Flash Programming (For Production)

**Advantages:**
- ✅ Persistent across power cycles
- ✅ No ESP32 needed after programming

**Disadvantages:**
- ⚠️ Slower (~15-20 seconds due to flash erase)
- ⚠️ Flash wear - limited to ~100K cycles
- ⚠️ Requires FPGA core with SPI passthrough
- ⚠️ Can brick device if power lost during flash

**Usage:**
```bash
# Use .bin bitstream for flash programming
curl -X POST http://10.0.4.94:3232/fpga-update --data-binary @impl/pnr/bitstream.bin
```

## Recommended Workflow

### Development Cycle (Fast Iteration)
```bash
# 1. Build in Gowin IDE
#    Output: impl/pnr/project.fs

# 2. Upload via JTAG SRAM (5-10 seconds)
curl -X POST http://10.0.4.94:3232/fpga-jtag-sram --data-binary @impl/pnr/project.fs

# 3. Test immediately
#    FPGA reconfigures instantly after upload

# 4. Iterate rapidly - no flash wear!
```

### Production Release (Persistent)
```bash
# 1. Final build in Gowin IDE
#    Output: impl/pnr/project.bin

# 2. Upload to flash (15-20 seconds)
curl -X POST http://10.0.4.94:3232/fpga-update --data-binary @impl/pnr/project.bin

# 3. Power cycle to verify persistence
#    FPGA boots from flash automatically
```

### Bootstrap Scenario (No Bootloader)

This is the **killer feature** - even if your flash is completely empty or corrupted:

```bash
# 1. Load minimal bitstream via JTAG that connects SPI flash pins
curl -X POST http://10.0.4.94:3232/fpga-jtag-sram --data-binary @minimal_spi_bridge.fs

# 2. Now you can program flash normally
curl -X POST http://10.0.4.94:3232/fpga-update --data-binary @full_bitstream.bin

# 3. No bootloader needed! JTAG is the ultimate recovery.
```

## File Format Reference

### .fs Files (JTAG SRAM Programming)
- Generated by Gowin IDE: **Place & Route → Generate File → SRAM Programming File**
- Format: Raw bitstream ready for JTAG CFG_IN instruction
- Usage: Direct upload to `/fpga-jtag-sram` endpoint
- No conversion needed

### .bin Files (SPI Flash Programming)
- Generated by Gowin IDE: **Place & Route → Generate File → Flash Programming File**
- Format: Raw bitstream for SPI flash (address 0x000000 or 0x100000)
- Usage: Upload to `/fpga-update` endpoint
- Persistent across power cycles

## Technical Details

### JTAG Programming Sequence

The implementation uses Gowin-specific JTAG instructions:

1. **IDCODE (0x09)** - Verify device (GW2A-18: 0x0900281B)
2. **JPROGRAM (0x3C)** - Clear SRAM configuration
3. **CFG_IN (0x39)** - Shift bitstream data into SRAM
4. **JSTART (0x3D)** - Start FPGA with new configuration

No SVF conversion needed - direct bitstream upload!

### Supported Devices

Current implementation supports:
- ✅ GW2A-18 (IDCODE: 0x0900281B) - Papilio RetroCade
- ✅ GW2AR-18 (IDCODE: 0x0100481B)
- ✅ GW1N-1 (IDCODE: 0x0900181B)
- ✅ GW1NR-9 (IDCODE: 0x0100181B)

Device is automatically detected and verified before programming.

### Performance Comparison

| Method | Time | Flash Wear | Persistent | Works w/ Empty Flash |
|--------|------|------------|------------|---------------------|
| JTAG SRAM | ~5-10s | None | No | ✅ Yes |
| SPI Flash | ~15-20s | Yes (~100K cycles) | Yes | ❌ No |

## Troubleshooting

### FPGA not detected via JTAG
- Check WiFi connection (OTA server must be running)
- Verify JTAG pin connections (see Hardware Connections above)
- Check that FPGA is powered
- Try reading IDCODE: the log will show detected device

### Upload succeeds but FPGA doesn't configure
- Verify .fs file is generated from Gowin IDE
- Check bitstream is for correct device (GW2A-18)
- Try uploading a known-good bitstream (blink LED)

### JTAG slower than expected
- Normal speed: ~5-10 seconds for typical bitstream
- Network latency affects upload time
- JTAG clock speed is conservative for reliability
- Still 2-3x faster than flash programming!
